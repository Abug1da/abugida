# Abugida

Free Amharic learning site (theabugida.org). This branch (`rebuild`) is a from-scratch rebuild; the previous Vite + Firebase app and its content engine are on `content-engine`.

## Stack

- **Next.js 16** (App Router) + **Tailwind v4** + **shadcn/ui** (Base UI)
- **Postgres** through **Drizzle ORM**
- **Better Auth** (email + password), sessions and rate-limit counters stored in Postgres
- **Railway** hosts the app and the database; Cloudflare handles DNS (and R2 for audio, later)
- **Bun** for installs and scripts

## Getting started

Needs Docker for the local database.

```sh
bun install
docker compose up -d            # local Postgres on :5432
cp .env.example .env.local      # then set BETTER_AUTH_SECRET: openssl rand -base64 32
bun run db:migrate              # applies drizzle/ migrations
bun run dev                     # http://localhost:3000
```

## Database

- Schema lives in `src/db/`. `auth-schema.ts` is generated by Better Auth (`bun run auth:generate`); put app tables in their own files and export them from `schema.ts`.
- After a schema change: `bun run db:generate` writes SQL to `drizzle/`, then `bun run db:migrate` applies it. `bun run db:studio` opens a browser view of the data.
- Server code gets the database with `getDb()` from `@/db` and the session with `getSession()` from `@/lib/auth/server`.

## Deploying to Railway

The service and database are described in `.railway/railway.ts` (Railway infrastructure as code). It is not applied on push.

1. Install the Railway CLI, then `railway login` and create a project in the dashboard.
2. Connect the GitHub repo to the `web` service in the dashboard, and set `BETTER_AUTH_SECRET` (`openssl rand -base64 32`) and `BETTER_AUTH_URL` (the production URL, e.g. `https://theabugida.org`).
3. `railway link`, then `railway config plan` and `railway config apply` to create the Postgres database and apply the service settings.
4. Each deploy runs `bun run db:migrate` before switching traffic, and Railway waits for `/api/health` (which checks the database) to answer.
5. Point the domain at Railway. Redirect `www` to the apex domain, or sign-in from `www` fails Better Auth's origin check.
6. After the first deploy, check that sessions record real client IPs (the `ip_address` column of `session`), not a proxy address. Rate limiting keys on `X-Real-IP`.
