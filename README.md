# Abugida

Free Amharic learning site (theabugida.org). This branch (`rebuild`) is a from-scratch rebuild; the previous Vite + Firebase app and its content engine are on `content-engine`.

## Stack

- **Next.js 16** (App Router) + **Tailwind v4** + **shadcn/ui** (Base UI)
- **Postgres** through **Drizzle ORM**
- **Better Auth** (email + password), sessions and rate-limit counters stored in Postgres
- **Railway** hosts the app and the database; Cloudflare handles DNS (and R2 for audio, later)
- **Bun** for installs and scripts

## Getting started

Needs Docker for the local database.

```sh
bun install
docker compose up -d            # local Postgres on :5432
cp .env.example .env.local      # then set BETTER_AUTH_SECRET: openssl rand -base64 32
bun run db:migrate              # applies drizzle/ migrations
bun run dev                     # http://localhost:3000
```

## Database

- Schema lives in `src/db/`. `auth-schema.ts` is generated by Better Auth (`bun run auth:generate`); put app tables in their own files and export them from `schema.ts`.
- After a schema change: `bun run db:generate` writes SQL to `drizzle/`, then `bun run db:migrate` applies it. `bun run db:studio` opens a browser view of the data.
- Server code gets the database with `getDb()` from `@/db` and the session with `getSession()` from `@/lib/auth/server`.

## Deploying to Railway

The service and database are described in `.railway/railway.ts` (Railway infrastructure as code). It is not applied on push, and settings changed only in the dashboard show up as drift, so change that file instead.

1. Push the `rebuild` branch (the file deploys it; switch to `main` after merging).
2. Install the Railway CLI (5.42.1 or newer), `railway login`, create an empty project (`railway init`), and `railway link` from this folder.
3. `railway config plan`, then `railway config apply`. This creates the Postgres database and the `web` service connected to the repo.
4. Set `BETTER_AUTH_SECRET` (`openssl rand -base64 32`) and `BETTER_AUTH_URL` (the production URL) on `web` with `railway variables` or the dashboard, then redeploy.
5. Each deploy runs `bun run db:migrate` before switching traffic (stopped after 120 seconds), and Railway waits for `/api/health`, which checks the database.
6. Domains: theabugida.org and www.theabugida.org are custom domains on `web` (added with `railway domain`, since `railway.ts` can't register them). Cloudflare DNS has CNAMEs to Railway plus `_railway-verify` TXT records, all DNS-only (grey cloud): rate limiting trusts `X-Real-IP`, which Railway's edge overwrites. `www` redirects to the apex in `next.config.ts`, because Better Auth only accepts the `BETTER_AUTH_URL` origin. Leave the Google Workspace MX/SPF records alone.
7. After the first deploy, check:
   - `select ip_address from session order by created_at desc limit 5` shows real client IPs, not empty or a proxy address. If they're missing, every login shares one rate-limit bucket.
   - the build log lists every page as dynamic (`ƒ`);
   - sign-in sets a `__Secure-` cookie;
   - `railway config plan` shows no drift.
